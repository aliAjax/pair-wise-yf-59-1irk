# 帆船赛现场控制和申诉处理

竞赛官维护组别、航线、起航时间和处罚记录，计时员提交到达数据，裁判处理抗议、重赛、弃权和成绩更正；丈量员登记有效丈量证书和船员称重。丈量记录、参赛条目和成绩接成同一份放行依据。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62024`

## 放行依据（丈量 × 参赛 × 成绩）

- **按比赛时点核对**：每场开赛前按起航时点检查证书（有效期必须覆盖起航）和船员重量（不得超过该场重量上限）；称重只认比赛当天最近一次。
- **待核不占名次**：证书缺失/过期、当天无称重或重量超限的船进待核区，单独列出，不进入正式名次。
- **更新即重算**：证书或重量更新后立即重核放行；若正式名次已发布，旧版马上标记作废并另存一版“更正成绩”，历史版次原样留档可查。
- **先写入生效**：两位丈量员基于同一读数同时提交同一艘船称重时，先写入的读数生效，后到者看到当前读数并拿到冲突号（`CFT-xxx`），其提交不覆盖。
- **越权挡回**：只有丈量员可登记证书与称重；其他角色提交会被挡回，仅时间线留痕，不产生记录。
- **失败留单重试**：写入通道故障时，没落地的登记保存在发件盒（含重试次数与原因），通道恢复后可单条或批量重试。
- **升级补档**：旧版数据没有检验快照，升级时按比赛当天最近的丈量记录补一版放行快照；补不到有效核对的船留在待核，快照标注“升级补档”。

## 可用流程

- 竞赛控制：起航倒计时、开赛放行核对（已放行/待核数量）、仅已放行船只的名次和待核区。
- 丈量与放行：操作人身份切换、证书/称重登记、并发称重模拟、待重试队列、放行依据表、冲突号列表。
- 成绩发布：净用时录入与重算、发布/重发正式成绩、当前版与已作废版次留档。
- 抗议处理：提交抗议、进入复核、支持抗议或维持原成绩，判罚同时触发名次重算，操作保留时间线。
- 数据使用 localStorage（`regatta-control-v2`）持久化，读取旧键 `regatta-control-v1` 时自动迁移补档。
